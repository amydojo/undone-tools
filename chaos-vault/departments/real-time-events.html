Real-Time Events

A typed event taxonomy and a reconnecting client pattern for persistent event streams. Derived from Jellycat Tracker's SSE architecture — portable to any server-sent or WebSocket event source.

2 Reconstructed
Provenance
Donor · Jellycat Tracker

Jellycat Tracker tracked real-time stock changes, price updates, and wishlist events across multiple Jellycat product listings. The backend pushed events via Server-Sent Events (SSE); the client needed to remain connected across page focus changes, network interruptions, and server restarts. The typed event taxonomy ensured that each event type could be handled independently without a fragile if/else chain. The reconnecting client is the portable behavioral contract — the specific Jellycat event types are replaced here with generic examples.

⚠
Domain Events Replaced The original taxonomy was specific to Jellycat product tracking. The event type names used here are generic analogs. The retailer scraping bypass logic that populated some events is quarantined (DATA-002) and not reproduced.
CV-RTE-001

Typed Event Taxonomy

Reconstructed

A discriminated union of event types, each with a typed payload. Handlers register per-type — no switch statements, no shared payload shape assumptions.

PatternDiscriminated union (TypeScript) or tagged object (plain JS). Each event has a type string and a narrowed payload.
ExtensionAdd new event types by extending the union — existing handlers are unaffected.
RiskLow. The pattern is domain-neutral. Payload shapes are application-defined.
TAXONOMY DEFINITION 
// CV-RTE-001 · Typed Event Taxonomy (TypeScript)

// Define all event types as a discriminated union
type AppEvent =
  | { type: 'collection:item_added';    payload: { id: string; label: string } }
  | { type: 'collection:item_removed';  payload: { id: string } }
  | { type: 'collection:price_updated'; payload: { id: string; price: number } }
  | { type: 'user:session_started';    payload: { deviceId: string } }
  | { type: 'system:heartbeat';        payload: { uptime: number } }

// Handler registry — register once, fire many times
const handlers = new Map<string, Function>()

function on<T extends AppEvent['type']>(
  type: T,
  handler: (payload: Extract<AppEvent, { type: T }>['payload']) => void
) { handlers.set(type, handler) }

function dispatch(event: AppEvent) {
  handlers.get(event.type)?.(event.payload)
}

// Usage
on('collection:item_added', ({ id, label }) => {
  console.log(`New item: ${label} (${id})`)
})
CV-RTE-002

Reconnecting Client

Reconstructed

A thin wrapper around EventSource (SSE) that handles reconnection with exponential backoff, page visibility pausing, and a clean disconnect API. Keeps the application layer unaware of connection state mechanics.

Backoff1s → 2s → 4s → 8s → 16s → max 30s. Reset on successful message receipt.
VisibilityPauses reconnection attempts when document.visibilityState === 'hidden'. Reconnects immediately on focus return.
RiskLow. EventSource is well-supported. The reconnect logic is additive — it doesn't interfere with native SSE retry.
RECONNECTING CLIENT 
// CV-RTE-002 · Reconnecting SSE Client

function createReconnectingClient(url, onEvent) {
  let source, attempts = 0, timer, paused = false
  const DELAYS = [1000, 2000, 4000, 8000, 16000, 30000]

  function connect() {
    if (paused) return
    source = new EventSource(url)

    source.onmessage = e => {
      attempts = 0                        // reset backoff on success
      try { onEvent(JSON.parse(e.data)) }
      catch { /* malformed JSON — skip silently */ }
    }

    source.onerror = () => {
      source.close()
      const delay = DELAYS[Math.min(attempts++, DELAYS.length - 1)]
      timer = setTimeout(connect, delay)
    }
  }

  // Pause when tab is hidden
  document.addEventListener('visibilitychange', () => {
    paused = document.hidden
    if (!paused && !source?.readyState) connect()
  })

  connect()

  return {
    disconnect: () => { source?.close(); clearTimeout(timer) }
  }
}
