Vision Analysis

A cautious server-side image observation contract. Defines what the route sends, what the vision model returns, and what the caller is allowed to infer. Does not invent diagnostic scores.

1 Reconstructed 1 Experimental 1 Quarantined
Provenance
Donor · Let's Glo (vision route)

The original vision route accepted a JPEG blob, forwarded it to a multimodal model (GPT-4o or Claude), and returned structured observations. The portable part is the request/response contract: what gets sent, what the model is asked to do, and how the response is parsed and validated. The Smooth MD "skin health score" layer — which assigned invented numeric ratings to skin attributes — is excluded and quarantined. No diagnostic interpretation logic is reproduced here.

⚠
Domain Specificity Warning The original route was designed for skin analysis for a specific clinic software product. The general contract shape here is portable — but any deployment must define its own prompt, its own schema, and its own interpretation rules. Do not reuse the original prompt verbatim. It encodes Smooth MD assumptions.
CV-VIS-001

Server-Side Observation Contract

Reconstructed
Use casesAny route that accepts an image and returns structured observations without making clinical or diagnostic claims.
DependenciesAny multimodal LLM with vision input (OpenAI, Anthropic, Google). Prompts are project-specific and not included.
CautionThe model returns natural language. The contract defines a JSON envelope — not a scoring system. Do not add numeric scores without a validated methodology.
REQUEST CONTRACT 
// CV-VIS-001 · Observation Contract · Request shape
// POST /api/vision/observe
// Content-Type: multipart/form-data

Request {
  image: Blob          // JPEG, max 5MB, from CV-CAM-002
  context?: string   // optional caller-provided context string
  session_id: string // for audit logging — not stored with image
}
RESPONSE CONTRACT (safe shape) 
// CV-VIS-001 · Observation Contract · Response shape
// What the route returns — observations only, no scores

Response {
  ok:           boolean
  observations: string[]  // raw natural-language observations from model
  model:        string     // e.g. "gpt-4o" — for traceability
  latency_ms:   number
  // ↓ deliberately absent: scores, ratings, diagnoses, percentages
}

// Error shape — always return, never throw to client
ErrorResponse {
  ok:     false
  reason: 'model_unavailable' | 'invalid_image' | 'rate_limited' | 'unknown'
}
CV-VIS-002

Image Payload Formatter

Experimental
Use casesConverting a canvas Blob to the appropriate format for the target LLM vision API (base64 data URL vs. multipart).
RiskMedium. Base64 encoding increases payload size ~33%. Large images should be resized client-side before encoding.
DependenciesFileReader API or modern blob.arrayBuffer()
PAYLOAD FORMATTER 
// CV-VIS-002 · Image Payload Formatter (experimental)

async function formatForVision(blob, targetAPI) {
  // Resize if over threshold — vision models don't need full-res
  const MAX_BYTES = 1_200_000
  const resized = blob.size > MAX_BYTES
    ? await resizeBlob(blob, { maxDimension: 1024 })
    : blob

  if (targetAPI === 'openai') {
    // OpenAI expects base64 data URL
    const b64 = await blobToBase64(resized)
    return { type: 'image_url', image_url: { url: b64 } }
  }

  // Anthropic / others: multipart FormData
  const fd = new FormData()
  fd.append('image', resized, 'capture.jpg')
  return fd
}
⛔ CV-VIS-003 — QUARANTINED
CV-VIS-003
Skin Score Diagnostic Assigned 0–100 numeric scores to skin attributes (hydration, clarity, tone evenness). These scores were invented outputs of a prompt instructing the model to rate features — they have no clinical validation, no reproducibility guarantee, and no grounding in dermatological methodology. The model was effectively making up numbers.

Do not import. If you need to surface model output as "scores," implement a validated rubric with explicit uncertainty disclosure.
