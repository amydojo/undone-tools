Recovery Patterns

Patterns that assume real tasks deviate from the happy path and keep repair available without shame, panic, or full-flow collapse.

2 Reconstructed
Corrected Provenance
Donor · Fridge Web

Fridge Web was a mobile-first cooking companion. A person entered available ingredients, received several meal ideas, opened a recipe, and moved through a guided cook mode. Its strongest affective pattern was a small “Something feels off?” control inside the cooking flow that revealed specific recovery guidance when the meal was not behaving as expected. The invention is humane mid-task repair, not a smart-fridge freshness scanner and not merely an AI-confidence accordion.

CV-REC-001

“Something Feels Off?” Recovery Reveal

Reconstructed

A low-salience but accessible recovery hatch embedded at the exact point where deviation becomes noticeable. It treats mistakes, ambiguity, and unexpected results as normal conditions of the task rather than as user failure.

Use casesCooking, setup, creative tools, forms, task plans, camera capture, generated outputs, or any flow where “correct” behavior can drift while the user is still mid-task.
TriggerAlways available where repair is useful. It may also be contextually emphasized after an error signal, but should not require emotion inference.
RevealObservable symptom, plausible causes, safe adjustments, and a clear route back to the current task.
UX principleDeviation is normal. Recovery preserves agency. The interface does not scold, diagnose, or restart the whole flow.
RiskHiding the control so thoroughly that only confident users find it, or reducing it to generic “try again” copy.

STEP 3 OF 5 · PAN
Cook until the sauce lightly coats the spoon.
Keep the heat low and stir every 20–30 seconds.
RECOVERY OPTIONS
Too thin? Keep it on low heat for 1–2 more minutes.
Splitting? Remove the pan from heat and stir in one spoonful of water.
Sticking? Lower the heat and loosen the bottom gently. Your progress is still usable.

Open the recovery reveal. The primary task remains intact.

CV-REC-002

Lazy Secondary Enrichment

Reconstructed

Render the complete primary result first, then enrich it asynchronously with useful secondary guidance. Secondary failure never invalidates or removes the usable first result.

Use casesMeal results followed by swaps and recovery tips, scene identification followed by artifact styling, or any AI flow with a fast core and slower optional enrichment.
Phase 1Useful, complete enough to act on, and rendered immediately.
Phase 2Optional enrichment updates in place without stealing focus or remounting the primary surface.
Failure behaviorKeep Phase 1. Label enrichment as unavailable only when the missing detail matters.
RiskDuplicate enrichment calls, layout shift, or pretending the slow phase is required when it is not.
PATTERN SKETCH
async function loadWithEnrichment(input, render) {
  const primary = await loadPrimary(input)
  render({ primary, enrichment: null, enriching: true })

  try {
    const enrichment = await loadEnrichment(primary)
    render({ primary, enrichment, enriching: false })
  } catch {
    render({ primary, enrichment: null, enriching: false })
  }
}
