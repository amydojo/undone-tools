Recovery Patterns

UX and data-layer patterns for surfaces that depend on AI or async enrichment. Includes the optional "Something feels off?" confidence reveal and the lazy secondary enrichment pattern.

2 Reconstructed
Provenance
Donor · Fridge Web

Fridge Web was a smart-home / fridge inventory prototype that relied on an AI model to identify food items from photos and estimate freshness. Because AI outputs are probabilistic, the interface needed a design contract for communicating uncertainty without alarming users. The "Something feels off?" reveal is the portable surface pattern. The lazy secondary enrichment pattern handles the case where a first-pass response lands quickly but a deeper analysis takes longer.

CV-REC-001

"Something Feels Off?" Reveal

Reconstructed

An optional, non-alarming disclosure surface for AI-generated content. The UI presents results normally — but includes a low-key trigger that expands a confidence detail panel when the user chooses to investigate. The pattern never blocks the primary flow or leads with uncertainty.

Use casesAny AI-surfaced result where the model confidence is below a threshold, where the source data quality is low, or where the inference is unusually complex.
Trigger conditionCaller decides when to show the trigger — it is not shown by default for high-confidence results. Threshold is application-defined.
UX principleThe user is never forced to see the uncertainty. The trigger is accessible, not prominent. The reveal contains honest explanation, not apology.
RiskLow. Pure UI pattern. No business logic dependency.
IMPLEMENTATION SKETCH 
// CV-REC-001 · "Something feels off?" Reveal
// HTML structure — progressively disclosed confidence detail

// The result renders normally first
<div class="result-card">
  <h3>{result.label}</h3>
  <p>{result.summary}</p>

  // Optional trigger — only rendered when confidence is below threshold
  {#if result.confidence < 0.75}
    <button
      class="cv-recovery-trigger"
      data-target="confidence-detail-{id}"
      aria-expanded="false"
    >
      <span class="cv-trigger-arrow">▸</span>
      Something feels off?
    </button>

    <div
      id="confidence-detail-{id}"
      class="cv-recovery-reveal"
    >
      <p>Confidence: {result.confidence * 100}%</p>
      <p>{result.low_confidence_reason}</p>
    </div>
  {/if}
</div>

// JS: single accordion driver in cv.js handles all triggers

CV-REC-002

Lazy Secondary Enrichment

Reconstructed

A two-phase data delivery pattern. Phase 1 returns a fast, shallow result immediately (e.g. item name + category). Phase 2 enriches that result asynchronously with deeper analysis (e.g. freshness estimate, storage advice). The UI renders Phase 1 immediately and updates in-place when Phase 2 arrives.

Use casesAny AI pipeline where a fast first-pass response is available sooner than a complete one. Reduces perceived latency dramatically.
Phase 1 latency~800–1200ms (fast model, minimal prompt). Display immediately.
Phase 2 latency~3000–8000ms (full analysis). Update the existing card without re-mounting.
RiskLow-Medium. Requires careful DOM update logic to avoid layout shift when Phase 2 arrives. Use reserved space or skeleton loaders.
PATTERN SKETCH 
// CV-REC-002 · Lazy Secondary Enrichment

async function loadWithEnrichment(imageBlob, renderFn) {
  // Phase 1: Fast shallow call — render immediately
  const phase1 = await identifyItem(imageBlob)
  renderFn({ phase: 1, data: phase1, enriching: true })

  // Phase 2: Deep enrichment — update in-place, don't re-render
  try {
    const phase2 = await enrichItem(phase1.id)
    renderFn({ phase: 2, data: { ...phase1, ...phase2 }, enriching: false })
  } catch {
    // Phase 2 failure is non-fatal — Phase 1 result stands
    renderFn({ phase: 2, data: phase1, enriching: false, enrichFailed: true })
  }
}
