AI Validation

A four-stage reliability sequence for AI-generated structured data: validate the schema, attempt repair if malformed, regenerate with a corrected prompt if repair fails, and guarantee a safe fallback if all else fails. No silent failures.

1 Reconstructed 2 Tested
Provenance
Donor · Fridge Web

Fridge Web called an AI model to parse food item data from images and return structured JSON (name, category, freshness estimate). AI models frequently return malformed JSON, miss required fields, or hallucinate unexpected keys. Rather than crashing or silently returning partial data, the system implemented a layered reliability pipeline. The sequence — validate, repair, regenerate, guaranteed-fallback — is the portable, domain-neutral core of that approach.

CV-AIV-001

Validate → Repair → Regenerate → Fallback

Reconstructed

The complete four-stage sequence. Each stage only runs if the previous stage failed. The fallback stage always succeeds — it returns a known-safe object rather than an error.

Stage 1: ValidateCheck the raw model output against the expected schema. If valid, return immediately — skip stages 2–4.
Stage 2: RepairAttempt to coerce the malformed output into the expected shape (extract fields, parse embedded JSON, fill defaults).
Stage 3: RegenerateRe-call the model with a stricter prompt that explicitly describes the schema and includes a correction instruction. Max 1 regeneration attempt.
Stage 4: FallbackReturn a hardcoded, guaranteed-valid safe object. The app continues. Log the failure for investigation.
RiskLow. The sequence is purely defensive and does not alter the calling interface.
SEQUENCE CONTRACT 
// CV-AIV-001 · Validate → Repair → Regenerate → Fallback

async function reliableAICall(prompt, schema, fallback) {
  // Stage 1: Call + validate
  const raw = await callModel(prompt)
  const v1 = validate(raw, schema)
  if (v1.ok) return { data: v1.data, stage: 1 }

  // Stage 2: Repair
  const repaired = attemptRepair(raw, schema)
  if (repaired.ok) return { data: repaired.data, stage: 2 }

  // Stage 3: Regenerate (one attempt only)
  try {
    const raw2 = await callModel(strictenPrompt(prompt, schema, v1.errors))
    const v2 = validate(raw2, schema)
    if (v2.ok) return { data: v2.data, stage: 3 }
  } catch { /* fall through */ }

  // Stage 4: Guaranteed fallback — never throws
  logFailure({ prompt, schema, stage: 4 })
  return { data: fallback, stage: 4, usedFallback: true }
}

CV-AIV-002

Schema Validator

Tested

A lightweight, zero-dependency runtime schema validator for AI response objects. No Zod, no Ajv — just a portable function that checks field presence, type, and optionally range.

DependenciesNone. Vanilla JS. <40 lines.
Use casesStage 1 of CV-AIV-001. Also useful for any runtime type-checking of external data.
LimitationsNot a full JSON Schema validator — handles the common 80% case (required fields, type checks, enum membership). Complex nested schemas need Zod or AJV.
VALIDATOR 
// CV-AIV-002 · Schema Validator

function validate(data, schema) {
  const errors = []

  for (const [key, rule] of Object.entries(schema)) {
    const val = data?.[key]
    if (rule.required && (val === undefined || val === null)) {
      errors.push(`Missing required field: ${key}`)
      continue
    }
    if (val !== undefined && rule.type && typeof val !== rule.type) {
      errors.push(`Field ${key}: expected ${rule.type}, got ${typeof val}`)
    }
    if (rule.enum && !rule.enum.includes(val)) {
      errors.push(`Field ${key}: "${val}" not in ${JSON.stringify(rule.enum)}`)
    }
  }

  return errors.length === 0
    ? { ok: true, data }
    : { ok: false, errors }
}

// Example schema
const itemSchema = {
  name:     { required: true,  type: 'string' },
  category: { required: true,  type: 'string', enum: ['produce', 'dairy', 'other'] },
  freshDays:{ required: false, type: 'number' },
}
CV-AIV-003

Guaranteed Fallback Store

Tested

A static registry of per-schema fallback objects. Imported at build time — no async, no failure mode. When Stage 4 fires, the app never crashes.

ContractEach entry in the store must satisfy the schema it corresponds to. Failing to maintain this parity silently defeats the purpose of the pattern.
CautionFallback objects are intentionally minimal — they communicate "we couldn't get data" rather than fabricating plausible values. Do not add fake data to fallbacks.
FALLBACK STORE 
// CV-AIV-003 · Guaranteed Fallback Store

const FALLBACKS = {
  // Keys match schema IDs
  item: {
    name:      'Unknown item',   // honest, not fabricated
    category:  'other',
    freshDays: null,               // null = we don't know
    _fallback: true,               // flag for UI to show notice
  },
  observation: {
    observations: [],
    model:        'unavailable',
    latency_ms:   0,
    _fallback:    true,
  }
}

export function getFallback(schemaId) {
  return structuredClone(FALLBACKS[schemaId] ?? { _fallback: true })
}
